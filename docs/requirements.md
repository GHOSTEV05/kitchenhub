# Software Requirements Specification

## 1. Introduction

### 1.1 Purpose
The purpose of this Software Requirements Specification (SRS) is to define the functional and non-functional requirements of the restaurant management software. This document serves as a reference and development guide for the project team, stakeholders, and other interested parties throughout the software development lifecycle, including the design, implementation, testing, and maintenance phases.

### 1.2 Scope
The Minimum Viable Product (MVP) of the system will support inventory, sales, and order management, as well as the generation of administrative reports containing basic statistics based on data collected throughout the restaurant's operational workflow.

By implementing the proposed solution, restaurant staff will no longer need to perform repetitive manual tasks that typically reduce operational efficiency, resulting in a more streamlined workflow and an improved overall business operation.

### 1.3 Definitions, Acronyms and Abbreviations
- **SRS (Software Requirements Specification):** A formal document that describes the functional and non-functional requirements of the system, serving as the primary reference for its design, development, testing, and validation.
- **SaaS (Software as a Service):** A cloud-based software delivery model where users access the application through the internet without installing it locally. The application is hosted, maintained, and updated by the service provider.
- **MVP (Minimum Viable Product):** The first functional version of the system that includes only the essential features required to validate the product and provide value to its users.
- **API (Application Programming Interface):** A set of rules that enables communication between the frontend and the backend, allowing data to be exchanged securely and consistently.
- **REST (Representational State Transfer):** An architectural style for designing web APIs based on standard HTTP methods, enabling scalable and maintainable communication between software components.
- **RBAC (Role-Based Access Control):** An authorization model in which users are granted permissions according to their assigned roles within the system.
- **CRUD (Create, Read, Update, Delete):** The four basic operations that can be performed on stored data within the application.
- **Restaurant:** A business that prepares and serves food and beverages to customers. In KitchenHub, it represents the organization whose administrative operations are managed by the system.
- **Menu:** The collection of food and beverage items offered by the restaurant, including their descriptions, prices, and availability.
- **Product:** An individual item available for sale, such as a meal, beverage, or dessert, that is managed within the restaurant's menu.
- **Order:** A request made by a customer containing one or more products to be prepared and served by the restaurant.
- **Inventory:** The collection of ingredients, supplies, and other resources required for the restaurant's daily operations.
- **Dashboard:** A visual interface that provides summarized information and key business metrics to support operational monitoring and decision-making.
- **Report:** A structured presentation of business information generated by the system to support analysis, monitoring, and administrative decision-making.
- **Authentication:** The process of verifying the identity of a user before granting access to the system.
- **Authorization:** The process of determining which resources and actions an authenticated user is allowed to access based on their assigned role and permissions.
